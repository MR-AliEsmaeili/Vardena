# ACC-07 — ساختارهای کدینگ — گزارش پیاده‌سازی

**تاریخ:** ۲۰۲۶-۱۰-۲۶ · **وضعیت:** پیاده‌سازی فرانت‌اند؛ بک‌اند تغییر نکرده است.

## تحویل

- API فهرست/جزئیات/ایجاد/ویرایش/انتشار ساختار حساب در `frontend/src/api/accounting.api.ts`؛ تابع فهرست موجود `listCodingStructureVersions` حفظ و استفاده شد.
- مجوزهای `CodingStructure.View` و `CodingStructure.Configure`، query keyهای سازمان‌محور، routeهای list/new/detail/edit و گیت دقیق مجوز.
- صفحه مشترک ساختارها با مسیر coding: فیلتر URL و صفحه‌بندی سرور، فرم سطوح (عمق ۱..۸، عنوان، طول رقم، پیش‌فرض ثبت‌پذیری، نوع سطح)، جمع طول، جداکننده فقط نمایشی، جزئیات و انتشار با تأیید.
- فقط نسخهٔ draft قابل ویرایش/انتشار است؛ `code` در PATCH نیست؛ pattern نمایش داده‌شده متعلق به پاسخ سرور است.

## انطباق قرارداد

- هیچ endpoint یا مجوز بک‌اندی اضافه نشده است.
- `POST /coding-structures/:id/publish` بدون بدنه ارسال می‌شود.
- تابع موجود `getActiveCodingStructure` رفتار خطای 404 را در سطح API به `null` نگاشت می‌کند؛ تابع جایگزین یا duplicate برای فهرست ساخته نشد.
- `chartTree` و حساب‌های موجود invalidation/بازنویسی نشده‌اند.

## راستی‌آزمایی

- تست UI متمرکز ساختار تفصیلی در `src/features/accounting/structures/structure-admin-page.test.tsx`، تست‌های ناوبری/route، typecheck، lint، format، suite کامل و build در مجموعهٔ نهایی اجرا شده‌اند. پوشش اختصاصی ماتریس وضعیت/انتشار کدینگ در این PR محدود است و CI باید همان suiteهای سنگین را تأیید کند.
- ردیف «ساختارهای کدینگ» در `docs/frontend/coverage-matrix.md` به COMPLETE به‌روزرسانی شد.

## محدودیت / پیگیری

صفحهٔ کدینگ و تفصیلی از یک shell/فرم مشترک استفاده می‌کنند، ولی DTOها در شاخه‌های مستقل باقی مانده‌اند؛ فیلدهای مختص تفصیلی به بدنهٔ کدینگ و برعکس اضافه نمی‌شوند. تست‌های کامل action matrix برای coding structure به‌عنوان پیگیری CI ثبت شوند.
